# Star v0.1.0

Star v0.1.0 establishes the first executable contract for Tool, Field, and Box
composition.

## Features

- C++23 Modules project built by mcpp with a single `star` executable.
- `star tool list/info/run` for declarative Lua Tool packages.
- `star field list/info/run` with transparent Field-to-Tool `ctx:call`.
- `star box backend list`, `box inspect`, and argv-safe `box exec`.
- `star interface version/list/call` using NDJSON result envelopes.
- Typed Capability, Event, Error, ExecutionContext, and Result contracts.
- Session/Manifest permission intersection and call cycle/depth protection.
- TOML Manifest parsing without executing extension code.
- CLI projection and `--input-json` validation against one JSON Schema.
- Restricted Lua 5.4 environment without `os`, `io`, `debug`, or `package`.
- Docker and Podman local Backends plus Fake Backend contract tests.
- Firmware Binwalk Tool and firmware Field examples.

## Fixes

- `cffa687` makes Docker and Podman report only the `inspect` and `exec`
  capabilities implemented in v0.1.

## Tests

The release contains eight independently runnable C++ test binaries covering:

- CLI help and linked command workflows;
- Tool and Field end-to-end Lua execution;
- Capability success, permission, missing target, and cycle behavior;
- Event result invariants;
- argv-safe process execution;
- Manifest validation, deterministic discovery, and path escape rejection;
- Lua restriction, JSON conversion, and transparent child calls;
- Box references, Backend plans, and Fake Backend dispatch;
- CLI/JSON projection and JSON Schema validation.

GitHub Actions runs `mcpp build`, `mcpp test`, and linked-binary smoke tests on
Linux, macOS, and Windows.

## Compatibility

- mcpp: `2026.8.15.1`
- C++: C++23 Modules
- Lua: 5.4.7 through `mcpplibs.capi.lua` 0.0.3
- Manifest: `star.extension/v1`
- Interface protocol: `1.0`
- Backends: local Docker and Podman `inspect`/`exec`

## Known Limitations

- Extension installation, signatures, registry state, and lock records are not
  implemented; v0.1 discovers local packages.
- JSON Schema `$ref` is rejected.
- Docker/Podman create, lifecycle, logs, copy, TTY, and signal forwarding are
  not exposed yet.
- External Backend NDJSON adapters and remote authorities are deferred.
- Public packaging still needs a final decision about the existing Homebrew
  executable named `star`.

## Development Baseline

Future development should start from the contracts in `AGENTS.md` and the two
design drafts. Keep extension calls in-process through `ctx:call`; adding a
recursive `star` subprocess or direct Docker call inside Field code breaks the
v0.1 policy, cancellation, trace, and backend boundaries.
